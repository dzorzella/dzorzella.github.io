Da Windows a Linux: il mio percorso di virtualizzazione

Alcuni mesi fa ho deciso di effettuare il passaggio completo da un ambiente Windows a un setup Linux desktop. Questa transizione è il culmine di un percorso lungo e graduale, iniziato con Linux in VirtualBox, proseguito con dual boot, e culminato con Ubuntu come unico sistema operativo.

Una delle motivazioni principali di questo switch è stata la performance eccezionale che Linux offre, soprattutto se confrontata con la natura lenta e pesante di Windows. Tuttavia, nonostante l'efficienza del nuovo setup, avevo ancora bisogno di eseguire macchine virtuali Linux aggiuntive, essenziali per il mio percorso di apprendimento nel penetration testing e per esperimenti a basso costo.

Per affrontare questa esigenza, ho esplorato QEMU in combinazione con Virtual Machine Manager (usando KVM). Ho trovato questa soluzione eccezionalmente leggera, stabile e semplice da configurare.

Installazione di QEMU e Virtual Machine Manager

Prima di installare qualsiasi cosa, procediamo con il classico upgrade dei pacchetti di sistema: 

sudo apt update && sudo apt upgrade

A questo punto possiamo installare QEMU e Virtual Machine Manager: 

sudo apt install qemu-kvm libvirt-daemon-system libvirt-clients bridge-utils virt-manager

Una volta installato, dobbiamo aggiungere il nostro utente ai gruppi `libvirt` e `kvm` per ottenere i privilegi richiesti: 

sudo adduser $USER libvirt
sudo adduser $USER kvm

Per rendere effettive queste modifiche, è necessario effettuare il logout e il login.

Il servizio libvirtd

Il servizio libvirtd dovrebbe essere ora in esecuzione: 

sudo systemctl status libvirtd

Se non fosse attivo, avviamolo e abilitiamolo: 

sudo systemctl start libvirtd
sudo systemctl enable libvirtd

Montaggio del disco esterno all'avvio

Questo è richiesto solo se il file di storage della macchina virtuale (.qcow2) si trova su un disco esterno.

Step 1: Identificare il disco

Aprire un terminale ed eseguire: 

lsblk

Trovare il disco esterno (es. /dev/sdb1) e annotare il suo UUID: 

sudo blkid

Output di esempio: 

/dev/sdb1: LABEL="DATA" BLOCK_SIZE="512" UUID="6274Exxxxxxxxxxx" TYPE="ntfs" PARTLABEL="Basic data partition" PARTUUID="25373248-xxxx-xxxx-xxxx-xxxxxxxxxxxx"

Step 2: Creare il mount point

sudo mkdir /mnt/$USER/DATA

Step 3: Montaggio automatico con fstab

Aprire il file di configurazione `/etc/fstab`, che definisce come e dove le partizioni del disco e i dispositivi di storage devono essere montati al boot: 

sudo nano /etc/fstab

Aggiungere la riga in fondo, usando l'UUID scoperto precedentemente. Sebbene sia possibile usare /dev/sdb1, questo valore è noto a cambiare al reboot in caso di modifiche alla configurazione dello storage: 

UUID=6274Exxxxxxxxxxx /mnt/$USER/DATA ntfs defaults,nofail 0 2

Riavviare, lo storage sarà ora montato automaticamente sotto `/mnt/$USER/DATA`.

Approccio alternativo con startup script

Questo secondo metodo era il mio approccio di default prima di scoprire la funzionalità built-in di fstab.

Creare un file `/home/$USER/startup.sh`: 

#!/bin/bash
mkdir /media/$USER/DATA
mount -t ntfs /dev/sdb1 /media/$USER/DATA -o umask=0000,gid=1000,uid=1000

Impostare il file come root, dato che il mount di un disco esterno richiede privilegi root: 

sudo chown root:root startup.sh
sudo chmod 700 startup.sh

Per eseguire il mount ad ogni avvio, aggiungere la riga `@reboot /home/$USER/startup.sh` al crontab: 

sudo crontab -e
